# sand_ordered: списки теряют элементы и уходят в вечный цикл, когда в пешку пишет второй пир

Затрагивает любую пешку с упорядоченным списком (`list_link` и родня), в которую хоть раз записали два разных аккаунта. Конкурентность не требуется: после единственной чужой записи список ломается даже одиночными правками по очереди, с полным синком между шагами.

Версия: HEAD `aca268d` (2026-07-09), `land/` `list/` `pawn/` `unit/` не менялись с 2026-06-12.

## Три режима отказа

1. **Потеря + дубль.** Элемент пропадает из списка, другой появляется дважды. На случайных парах драгов двух пиров — 15-35% слияний, на чередующихся правках вылезает почти всегда.
2. **Вечный цикл.** `sand_ordered` собирает цикл в цепочке `next`, финальный обход `while( entry.next !== null )` (`land/land.ts:826`) не завершается. Пешка перестаёт читаться на всех репликах навсегда — юниты уже в ленде и разъезжаются по синку. Один раз то же место упало явно: `RangeError: Invalid array length at Array.push ... sand_ordered`.
3. **Поломка в одиночку.** A построил список, B добавил один элемент, синк. Дальше A один тащит элементы мышкой: 7/10 пар Lord'ов рушат список первым же перемещением, 10 перемещений подряд превращают 4 элемента в 2.

## Корень

`sand_ordered` собирает очередь по всем пирам (units читаются с `peer = $giper_baza_link.hole`), а связный список при этом ключуется по одному `self`. Когда один и тот же `self` записан двумя пирами, записи коллидируют. Ветка `peer === null` берёт ту же очередь, но ключует по `path()` (peer+self) — и там коллизии нет.

Живой ленд, 5 Sand'ов на 4 разных `self`, один `self` записан обоими пирами:

```
ожидание                                        5FuDL,rfLfi,tqzlZ,y5A0Q
peer = hole (так читает units, ключ = Self)      5FuDL,rfLfi,tqzlZ,5FuDL   <- дубль + потеря
peer = null (те же Sand'ы, ключ = Peer + Self)   5FuDL,rfLfi,tqzlZ,5FuDL,y5A0Q
```

Перезапись чужого `self` — не экзотика, а штатные операции списка: `cut` кладёт tombstone с тем же `self`, `move` зовёт `sand_move`, `splice` в ветке replace — тоже. Плюс `items(next)`: `items_vary` → `splice(next, 0, len)` → `$mol_reconcile` (`mol/reconcile/reconcile.ts:35`), который выравнивает по позиции, а не по ключу — сдвиг элемента на k позиций порождает k replace-записей чужих `self`.

## Что безопасно, а что нет

12 чередующихся операций двух пиров над списком из 12 ссылок, полный синк после каждого шага, 10 прогонов:

```
append (make)          : зависаний 0/10, дублей нет, 24/24 записи
insert (splice-insert) : зависаний 0/10, дублей нет, 24/24
cut                    : зависаний 5/10
move                   : зависаний 5/10, один RangeError, дожило 11.3/12
items(next)            : зависаний 3/10, дожило 9.3/12, дубли в 2 прогонах
```

С паузой в целую секунду между операциями (общего секундного окна нет вообще): `cut` виснет 3/8, `items(next)` — 8/8. Безопасна ровно одна вещь: вставка со свежим `self`.

## Попутные наблюдения

- Атомы сходятся когерентно, но в пределах секунды выигрывает не последний писатель, а больший Lord: `compare = time > lord > tick`, а `time()` — целые секунды (`time/time.ts:18`). Пир с меньшим Lord'ом секунду «не может» писать — его записи молча проглатываются.
- Тромбстоуны остаются в пешке навсегда: после 200 удалений на странице в 300 элементов одна перестановка дорожает с 5.4 мс до 29 мс (известная квадратичность, тут просто ещё одно подтверждение).

## Воспроизведение

Главное: ветка [`sand-ordered-repro`](https://github.com/Dev-cmyser/baza/tree/sand-ordered-repro) — модуль `repro/` в самом движке, четыре детерминированных сюжета с повествованием в консоли, 2.2 секунды на всё:

```
npx mam giper/baza/repro
node giper/baza/repro/-/node.js             # все сюжеты
node giper/baza/repro/-/node.js story=solo  # solo | pair | cycle | root
```

Сюжет 1 — поломка одиночными правками после единственной чужой записи; сюжет 2 — потеря+дубль при правках по очереди (обе реплики сходятся на одном и том же битом списке); сюжет 3 — список перестаёт читаться (`RangeError` из `sand_ordered`, в дочернем процессе с таймаутом); сюжет 4 — корень: та самая табличка Self против path() на живой пешке.

Дополнительно:
- `bog/crdt-benchmarks/benchmarks/giper-baza/merge-bug.mjs` — исходный июльский repro, 6 из 12 слияний теряют текст.
- `bog/crdt-benchmarks/benchmarks/giper-baza/figmol-coedit.mjs` — стенд со статистикой по всем операциям списка: два реальных реплики со своими `$`-контекстами и Auth, общий ленд, обмен паками. Печатает таблицу выше, ~12 минут.

## Гипотеза фикса

Не реализована и не проверена, но напрашивается из корня: в `land/land.ts:708-832` ключевать связный список по `path()` всегда, когда очередь собрана по всем пирам, а на выходе схлопывать по `by_self`-победителю. Изменение локальное — одна функция — но это сердце CRDT, трогать стоит тому, кто держит инварианты движка в голове. Тест-батарея для проверки готова (стенд выше покрывает все пять операций, оба режима отказа и одиночный сценарий).
