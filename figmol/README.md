# Figmol

Конструктор сайтов на канвасе: собираешь страницу из блоков, по кнопке получаешь
живой сайт на GitHub Pages и полноценный $mol-проект в своём репозитории.
План и продуктовые решения — в [PLAN.md](./PLAN.md).

## Структура

```
schema/    Giper Baza entities: home, site, page, node
store/     чтение и запись документа; общий для канваса, панелей и инспектора
blocks/    реестр: размеры и пресеты kind'ов, шаблоны секций — чистые данные
app/       редактор
  start/     экран «сайта ещё нет» с кнопкой создания
  tools/     палитра примитивов (иконки слева)
  side/      левая панель редактора
  pages/     список страниц, название и адрес текущей, удаление
  blocks/    палитра блоков builderui и секций-шаблонов
  layers/    дерево нод текущей страницы
  row/       строка списка боковой панели (общая для страниц и слоёв)
  canvas/    канвас: pan, zoom, выделение, drag, resize, drop в контейнеры
    shape/     один элемент на листе (и шейпы его детей)
  inspector/ панель свойств выделенного элемента
    field/     строка «подпись — контрол»
    number/    числовое поле без степперов
gen/       генератор MAM-проекта из снимка сайта
  snap/      снимок дерева из Базы в обычный JSON
deploy/    публикация на GitHub
  github/    клиент REST API: репозиторий, коммит, Pages, статус сборки
  publish/   панель «Опубликовать» с журналом шагов
mine/      своя IndexedDB + фолбэк мастеров (нужен на общем localhost-origin)
```

## Как устроено

В домашнем Land'е пользователя лежит только ссылка на сайт, а сам сайт — корневая
пешка отдельного Land'а. Так проект можно будет отдать по ссылке, не отдавая
аккаунт. Страницы и все ноды живут пешками внутри этого же Land'а: открыть проект
стоит один синк.

Land под сайт захватывается по кнопке на стартовом экране, а не сам собой:
`land_grab` считает Proof-of-Work, и задача с этим расчётом кешируется фиброй,
которая её запросила. Нажатие кнопки — одна такая фибра, она переживает
приостановки Базы. Тот же вызов из рендера начинал бы расчёт заново на каждом
ретрае.

Фрейм с непустым `Direction` — это flex-контейнер: дети раскладываются потоком, их
X и Y не значат ничего, а драг внутри такого фрейма меняет порядок в `Kids`.
Куда попадёт элемент, решает самый глубокий фрейм под курсором; координаты при
переносе пересчитываются от замеров DOM, а не от сохранённых X/Y — внутри
авто-раскладки эти два ответа расходятся.

Геометрия нод хранится в пикселях листа. Панорама и зум — свойство вьюпорта, они
накладываются одним CSS-трансформом на `World` и в Базу не пишутся.

Во время перетаскивания живой прямоугольник лежит в атоме `draft`, а в Базу
уходит один раз на `pointerup`. Иначе один драг превратился бы в сотни CRDT-юнитов.

Блоки `bui_*` рисуются настоящими компонентами `bog/builderui` — тем же кодом,
который получит опубликованный сайт. Клики по ним гасятся стилями: на канвасе
важно выделить блок, а не пользоваться им. Исключение — `bui_card`, он держит
внутри чужие ноды, и им клики нужны.

Секция — не отдельный kind, а фабрика: клик в палитре пишет в Базу готовое
поддерево из обычных фреймов, текстов, кнопок и `bui_*`. Поэтому секцию можно
разобрать теми же инструментами и генератору про неё знать нечего.

Палитра builderui по умолчанию тёмная, а лист — это страница сайта. Атрибуты
`bog_builderui_base` / `bog_builderui_lights` висят на `Sheet` канваса, и ровно
их же генератор ставит на корень собранного проекта — иначе редактор и сайт
разошлись бы в цвете.

## Публикация

Кнопка «Опубликовать» в шапке отдаёт правую панель (вместо инспектора)
`$bog_figmol_deploy_publish`. Файлы для неё считает `publish_files()` в
`app.view.ts`: снимок сайта из Базы → `$bog_figmol_gen.files()`. Имя репозитория
и имя модуля в исходниках — одно и то же `publish_name`, иначе собранный бандл
уедет мимо страницы, которая его ищет. Первое открытие панели подставляет имя из
заголовка сайта, дальше оно принадлежит пользователю.

## Шаринг по ссылке

Сайт — корневая пешка своего Land'а с пресетом `[[null, rank_read]]`, поэтому
ссылка на Land и есть весь механизм: выдавать и мигрировать нечего. Адрес вида
`#!site=<land>` (кнопка «Поделиться» кладёт его в буфер) заставляет
`store.site()` читать этот Land напрямую, минуя домашнюю запись.

Может ли этот браузер писать, решает `store.writable()`: ранг своего ключа в
Land'е сайта. Чтение `Title()` там обязательно — права приезжают Gift-юнитами
вместе с данными, и без чтения данных Land просто не синкается.

Пока прав нет, редактор показывает сайт целиком, но без единого контрола,
который бы не сработал: нет палитры примитивов, нет блоков, нет полей страницы,
нет инспектора, ручки ресайза не рисуются, драг только панорамирует. Выделение
работает — по нему смотрят слои. В шапке плашка «только чтение» и ссылка «Мой
редактор» (`arg * site null`).

Совместного редактирования нет: чужой ключ ранга `post` в Land не выдаётся.

## Undo

Журнал живёт в `store`: список пар замыканий «как отменить / как повторить».
Все правки и так идут через `*_edit`-методы стора, так что описание шага назад —
это просто значение, которое там было. Глубина 100.

Журнал намеренно нереактивный: сеттер поля — это тело `@$mol_mem_key`, и запись
в атом изнутри другого атома открывает цикл инвалидации. История — свойство
сессии, а не документа, и читают её только два хоткея.

Правки одного поля подряд склеиваются по тегу (900 мс): набранное слово — один
шаг назад, а не шаг на букву. Пустой тег не склеивается никогда — два драга
подряд остаются двумя жестами.

Удаление ноды или страницы только отцепляет ссылку (База append-only), поэтому
отмена удаления просто возвращает ссылку на прежнее место — поддерево живо.

## Хоткеи

- `⌘Z` / `Ctrl+Z` — отменить, `⌘⇧Z` / `Ctrl+Y` — повторить
- `⌘D` — дублировать выделенное вместе с поддеревом
- стрелки — сдвиг на 1px, с Shift на 10px (не для нод внутри авто-раскладки)
- `Escape` — снять выделение, `Delete` / `Backspace` — удалить

Слушатель висит на `window`, а не на `$mol_hotkey` корня: плагин слушает DOM-узел
своего view, а на холодной загрузке фокус на `<body>` — выше приложения, и до
него событие не доходит. Тот же слушатель закрывает inline-редактор подписи по
клику вне его: канвас видит только те нажатия, что попали в канвас.
